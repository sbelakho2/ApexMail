# ci/required-lanes.txt — the lanes a release blessing MUST record (T1, plan
# rule 1: "Required means recorded"). One lane id per line; blank lines and
# #-comments are ignored. A blessing whose requiredLanes map is missing a row
# for any lane here, or records it as anything other than ok, is refused by
# the deploy host (ci/lib.sh gate_blessing_refusal).
#
# Lane ids are MECHANICAL: "<stage>.<slug>" where slug is the ci_check label
# lowercased with every non-alphanumeric run collapsed to one dash — the same
# algorithm ci/lib.sh ci_check_lane_id applies when a stage records its lanes
# into the run manifest. tools/check_waivers.py --check-lanes (the
# validate.waivers lane) proves every row here names a lane a stage actually
# runs; a row with no producing check fails CI.
#
# Not listed here, deliberately:
#   * test.coverage-ratchet — recorded every run, but CI_COVERAGE_CHECK is
#     advisory by declared default, and an advisory lane cannot gate a blessing;
#   * checks with DYNAMIC labels (per-image trivy scans, docs/ui gate loops) —
#     their results are recorded in the run manifest but their ids vary per run;
#   * deploy-line stages (images/migrate/deploy/verify/notify) — the deploy
#     line is verified by .gate-blessing.json membership, not this ledger.
# The former test.browsers / test.php rows retired with the PHP mirror
# (2026-10-28); validate.kiwi-mirror-parity joined the same day.
#
